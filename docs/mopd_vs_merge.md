# 为什么 MOPD（多教师在线蒸馏）比权重合并好——以及它还不够好的地方

*所有数字都来自本仓库的原始结果（`results/<model>/`、`analysis/dev_selection.json`），由 `scripts/summarize.py` / `scripts/analyze_failures.py` 生成。HLE 准确率为审核后的口径。*

## 一句话

**MOPD 好在「行为健全、可控」，不好在「分数」。** 在同一批专家上：
- 权重合并（Linear / TIES）会让模型出现**任何单个专家都没有的病态行为**：抄回 prompt 模板、整段输出 bash 代码；
- MOPD 学生的输出和 base 一样干净，只是忠实地变成了教师的样子。

但在本实验的专家质量下，MOPD 的宏平均（−0.11）只比最终合版模型 TIES（−0.15）略好，**低于 Linear（+0.55）**，三者的差别都在置信区间内。下面先讲证据，再讲机制，最后讲它为什么还没赢、怎样才能赢。

## 1. 证据：行为完整性（HLE 500 题的原始输出）

| 模型 | 有效最终答案 | 抄回模板 `Answer: {your chosen answer}` | 整段 bash 代码、无答案 | judge 假阳性 | 回答中位长度（字符） | HLE（审核后） |
|---|---|---|---|---|---|---|
| base | 495 | 0 | 0 | 8 | 1444 | 2.80 |
| expert_hle（教师） | 491 | 0 | 0 | 0 | 467 | 4.20 |
| merged_linear | 469 | **27** | 1 | **32** | 439 | 4.80 |
| merged_ties（最终合版） | **284** | 4 | **198** | 17 | 138 | 3.40 |
| **mopd** | **495** | **0** | **0** | **3** | 328 | 3.40 |

- **MOPD 是唯一一个格式完整度和 base 持平的单模型**：495/500 都给出了有效答案，没有一次抄回模板，也没有一次答非所问。
- **TIES 有 40% 的题被终端专家「接管」**：直接输出 bash 代码块，没有答案。
- **Linear 有 27 题把模板原样抄回**。
- **MOPD 的输出最容易判分**：judge 假阳性只有 3 个（base 是 8，Linear 是 32）。也就是说，它的分数最不依赖判分器的宽松程度。Linear 的 HLE 原始 judge 分数是 11.2，审核后是 4.8，虚高的部分几乎都来自合并造成的格式错乱。MOPD 原始是 4.0，审核后是 3.4，几乎没有虚高。

## 2. 证据：宏平均与各项（相对 base，配对 bootstrap 95% CI）

| 模型 | HLE | ASI | TB2 | SWE | 宏平均 |
|---|---|---|---|---|---|
| merged_linear | +2.00 [−0.4, +4.4] | −1.17 | +1.35（第二次运行为 0） | 0 | **+0.55 [−0.4, +1.6]** |
| merged_ties（最终） | +0.60 | −1.20 | 0 | 0 | −0.15 [−0.9, +0.5] |
| **mopd** | +0.60 | −1.06 | 0 | 0 | **−0.11 [−0.8, +0.5]** |

- 相对最终合版模型（TIES），MOPD 在 HLE 上打平，在 ASI 上略好（0.14 vs 0.00），宏平均略好，但都在噪声范围内。
- 相对 Linear，MOPD 在 HLE 上低 1.4 个百分点（也在噪声内）。Linear 在 TB2 上多解出的 1 题，第二次运行没有复现。
- TB2 和 SWE 三者都是 0。其中 SWE 的评测配置有缺陷，见 README §8 第 6 条。

**所以「MOPD 分数更高」这个说法，本实验不支持。本实验支持的是：MOPD 没有带来合并式的退化。**

## 3. 机制：为什么合并会坏，蒸馏不会

**权重合并的问题出在「在参数空间里按人定的规则硬算」。**

1. **网络是非线性的**。两个专家各自有效的增量 ΔW₁、ΔW₂，加在一起后的行为不等于两种行为的叠加。哪些输入会被哪个专家「接管」，事先无法预测。
2. **每条规则都会改变行为，但规则是人定的**：
   - Linear 的 1/4 系数会把每个专家的能力都稀释到四分之一。HLE 专家的「Answer + Confidence」格式被稀释后不够稳定，于是出现抄模板。
   - TIES 剪掉 80% 小幅值后，对同号增量做「不相交平均」，不再除以 4。幅值最大的终端专家几乎以全强度保留下来，接管了 40% 的 HLE 回答。
   - 剪枝率、缩放方式、符号选举，每一项都是超参数，而它们和最终行为之间没有可优化的目标。
3. **合并没有输入条件**：同一组参数要同时服务所有领域，没有机制让「HLE 题用 HLE 专家、终端题用终端专家」。
4. **评价是离线的**：合并时既不看模型在真实输入上会生成什么，也不看生成结果对不对。

**MOPD 把冲突交给了优化目标，而不是规则。**

1. **目标定义在输出空间**：对每一个 token，让学生的分布贴近对应领域教师的分布（反向 KL）。「学生应该说什么」由教师逐 token 给出，不需要人去设系数和剪枝率。
2. **按输入路由教师**：HLE 类 prompt 由 HLE 教师监督，ASI 类 prompt 由 ASI 教师监督。领域之间的冲突，由梯度在学生的 LoRA 参数里找一个同时满足两边的解，而不是在参数空间里取平均。
3. **在线（on-policy）**：训练数据是学生自己生成的回答。学生在哪里会犯错，就在哪里被纠正（例如开始抄模板、开始写 bash），这正是离线 SFT 和权重合并都做不到的。
4. **反向 KL 偏向「选定一种模式」**：学生会稳定地采用教师的主要格式，而不是在几种格式之间摇摆，所以格式完整。
5. **可扩展**：学生不必和教师同结构、同大小。这条路线可以直接推广到「用多个小专家去教一个更大的学生」，权重合并做不到这一点。

## 4. 为什么 MOPD 还没在分数上赢

1. **教师就不强**：两个教师是用代理数据训练的（GSM8K 代替 HLE，CSQA 模板代替 ASI）。ASI 教师在 ASI 上比 base 还差（0.21 vs 1.20）。蒸馏是忠实的传递：学生在 ASI 上的回答长度从 320 token 塌缩到约 43 token，正好复制了教师的模板化短回答（`curves/stage2_metrics.png`）。**蒸馏的上限是教师。**
2. **只用了 2 个教师**：SWE 和终端专家没有作为教师参加 MOPD（这两项是 agent 型任务，在线采样代价太高）。所以 MOPD 在这两项上没有任何学习信号，开发集 loss 也明显高于合并模型（终端 2.31 vs 0.83–0.99）。合并模型「白拿」了这两个专家的参数，只是没变成分数。
3. **训练量小**：152 步，每步 32 条采样，约 2.6 GPU·h。合并几乎零成本（约 0.05 GPU·h）。
4. **TB2 和 SWE 是地板**：四项里有两项所有模型都是 0，宏平均的差别只能来自 HLE 和 ASI 两项，而这两项都在噪声范围内。

## 5. 怎样让 MOPD 真正超过合并（下一步）

1. **先把教师训强**：用真实的多轮 agent 轨迹训练 TB2 / SWE 专家，用「Explanation / Answer / Confidence」格式的高难推理数据训练 HLE 专家，用科学计算代码数据训练 ASI 专家。目标是每个教师都在本领域显著超过 base。
2. **4 个教师全部纳入**，对 agent 型任务用离线轨迹 + 少量在线回合，降低采样成本。
3. **用多教师生成的数据蒸馏更大的学生**（例如 Qwen3-14B）：先按结果过滤、做 SFT，再做在线蒸馏。学生学到的是专家之间的共性能力。
4. **加一项对 base 的 KL 约束**（在通用 prompt 上），防止学生丢掉 base 原有的能力（例如本实验中 ASI 的退化）。
5. **用生成式开发集选模型**：每个领域留几十条做真实生成 + 格式检查。teacher-forced loss 选中了 TIES，却完全看不出它的格式接管。

## 结论

在这批（偏弱的）专家上，MOPD 和权重合并在分数上打平，都在噪声范围内。但两者的失败方式完全不同：
- **合并的失败不可预测、不可诊断**：抄模板、格式被某个专家接管，而这些都不是任何一个专家原本的行为；
- **MOPD 的失败可预测、可诊断**：学生会变成教师的样子，教师有什么问题，学生就有什么问题。

后者可以通过改进教师直接修复，前者只能靠继续调人定的规则去碰运气。这就是我们认为蒸馏路线比权重合并更值得投入的原因，也是下一轮实验要验证的核心假设：**教师变强之后，MOPD 的分数优势能否显现。**
