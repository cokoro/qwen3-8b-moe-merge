# 把四个专家变成一个模型：权重合并为什么不太对，蒸馏为什么更值得做

*Qwen3-8B × 4 个 LoRA 专家 × {Linear, TIES, MOPD} 的一次完整实验记录。数字均来自本仓库 `results/summary.csv`，可由 `scripts/summarize.py` 从原始结果重新生成。*

## 一句话结论

三种把 4 个专家变成单一模型的方法，四项宏平均相对 Base 都没达到 +3：Linear +0.82，TIES（按开发集选出的最终模型）+0.04，MOPD 蒸馏 +0.07，都远低于 +3，基本在噪声范围内。真正的瓶颈不在「怎么合」，而在「专家本身有没有能力」。不过实验也给出了两个清楚的现象：TIES 会让一个专家的输出格式接管整个模型；蒸馏不会出现这种接管，但它也忠实地复制了教师的缺点。

## 出发点：我对「模型融合」的看法

做这个实验之前，我的判断是：

- **不要做权重融合**。权重合并靠人定的规则：系数、剪枝率、符号投票。这些规则里「人的东西」太多，它们不是从数据里学来的聪明规则，而是对参数空间的粗暴假设。合并之后既保不住各专家的能力，还可能伤到基座原有的能力。
- **应该做蒸馏**。让学生在自己的采样上，直接去拟合专家的输出分布，冲突交给优化器在输出层面解决，而不是在参数层面硬算。
- **更好的方式**是从各个专家的数据里提取共性：用两个（或多个）小专家生成的数据去蒸馏一个大模型，找专家之间的「高级共性」。
- 题目要求宏平均 +3 个点。我的预期是：**模型融合做不到 3 个点，用小专家蒸馏大模型有可能做到。**

这篇文章用实验数据检验这些判断，哪些被支持、哪些没被支持，都如实写。

## 实验设置（简版）

- 基座：Qwen3-8B（题目允许 7B 级），bf16，non-thinking。
- 4 个专家：每个专精一个 benchmark（SWE-bench Pro、HLE、ASI-Bench、Terminal-Bench 2.0），LoRA r16，500 步，种子 42。
- 三种得到单一模型的方式：
  1. **Linear**：4 个 LoRA 增量等权平均；
  2. **TIES**：每个专家剪掉 80% 小幅值更新，按多数派选符号，只平均同号部分；
  3. **MOPD**（多教师 on-policy 蒸馏）：学生 = 基座 + 新 LoRA，在自己生成的回答上逐 token 拟合对应领域教师的完整词表分布（反向 KL）。
- 评测：同一推理服务、同一模板、同一预算。HLE 500 题（纯文本）、ASI 60 题、TB2 74 题、SWE-Pro 子集。

## 结果

| 模型 | HLE | ASI | TB2 | SWE | 宏平均 | Δ vs base [95% CI] |
|---|---|---|---|---|---|---|
| base | 2.80 | 0.45 | 0.00 | 0.00 | 0.81 | — |
| merged_linear | 4.80 | 0.39 | 1.35 | 0.00 | 1.64 | +0.82 [0.0, +1.8] |
| merged_ties（最终） | 3.40 | 0.00 | 0.00 | 0.00 | 0.85 | +0.04 [−0.5, +0.6] |
| mopd | 3.40 | 0.14 | 0.00 | 0.00 | 0.88 | +0.07 [−0.5, +0.6] |

（ASI 为 v2：v1 的评测环境缺少任务声明的依赖包，修正后重跑。）

（HLE 为审核后的准确率；专家自己的 benchmark：expert_hle 4.20、expert_asi 0.21、expert_terminal 0.00、expert_swe 0.00。）

## 观察 1：权重合并的「收益」很大一部分来自格式，而不是能力

看两个现象：

- **TIES 有 40% 的 HLE 回答（198/500）变成了一个 bash 代码块**，这是终端专家的输出格式。原因在 TIES 的算法里：Linear 把每个专家的增量乘 1/4，大家都被稀释了；TIES 先剪枝、选符号，再对同号的增量做「不相交平均」，不再除以 4。幅值最大的那个专家（这里是终端专家）的主方向几乎以全强度保留下来，于是它的输出格式在所有输入上都占了上风。这正是「人定的规则」带来的问题：剪枝率、是否缩放、怎么选符号，每一个都是人拍的，而每一个都会实实在在地改变模型的行为。
- **Linear 在 HLE 上 +2.0**（第二次运行 +1.6），主要来自「给出一个短的最终答案」这种格式上的变化（HLE 专家是用 GSM8K 训练的），而不是推理能力变强了。同时 Linear 也有 27 题直接照抄了 prompt 里的模板 `Answer: {your chosen answer}`，说明格式层面的干扰在 Linear 里同样存在，只是被稀释了。
- ASI 上所有模型都在地板（60 题里最多 2 题拿到部分分），合版前后的差别只有一两道题，看不出规律。（早先版本说「ASI 专家背下模板、不写代码」，这是错的：它在 60/60 题都写了代码，失败在于代码运行报错。）

这些都支持我原来的看法：权重合并是在参数空间里按人定的规则硬算，模型具体会变成什么样，规则本身控制不了。

## 观察 2：裁判也会被骗——8B judge 的假阳性

HLE 官方用 o3-mini 判分，我们没有可用的 API，只能用本地 Qwen3-8B 当 judge。审核时发现一个很有代表性的问题：

- merged_linear 有 27 题直接把 prompt 里的格式模板抄了回来：`Answer: {your chosen answer}`；
- judge 的 prompt 里带着标准答案，8B judge 于是把标准答案当成「模型的回答」抽了出来，判为正确；
- 原始 judge 给 merged_linear 的分数是 11.2%，审核后只有 4.8%。

我们加了一层对所有模型统一适用的确定性审核：选择题直接比字母；非选择题要求模型有真实的最终答案，judge 抽取的答案必须出现在模型回答里，数值答案要数值相等。**这件事本身就是这次实验最重要的方法论教训之一：在分数很低的区间里，评测噪声可以轻易超过模型之间的真实差距。**

## 观察 3：蒸馏忠实地复制了教师——包括教师的缺点

MOPD 的学生（基座 + 新 LoRA）在自己的采样上，逐 token 拟合对应领域教师的完整分布。结果：

- **没有出现格式接管**：HLE 里没有一个代码块回答，也没有一个模板回声。冲突交给输出分布去解决，确实比在参数空间里平均干净；
- **但是也没有带来提升**：HLE +0.6，ASI 仍然低于 base；
- 训练曲线显示，在 ASI 的训练 prompt（CSQA 代理题）上，回答长度从 320 token 很快塌缩到约 43 token：学生学会了教师在代理题上的模板化短回答。真实 ASI 题目上它仍会写代码，但分数和教师一样在地板。

蒸馏是一个忠实的传递过程：教师有什么，学生就学什么，**包括缺点**。在教师本身没有能力的情况下，蒸馏不可能创造出能力。

更完整的对比（逐项证据表和机制分析）见 [`mopd_vs_merge.md`](mopd_vs_merge.md)。

## 那么，「蒸馏能到 3 个点」被证实了吗？

**没有被证实，但也没有被否定。** 这次的实验条件下，没有任何方法能接近 +3：专家是用代理数据训练的（GSM8K 代替 HLE，CSQA 模板代替 ASI，单轮 NL→bash 代替多轮终端 agent），在各自的 benchmark 上就没有显著超过 base。合版也好，蒸馏也好，都只能重新分配专家已有的能力。

但有两点和最初的判断一致：

1. 权重合并的行为是不可控的。TIES 的格式接管是一个很直接的反例：按「人定的规则」去合参数，得到的模型会出现任何单个专家都没有的病态行为；
2. 蒸馏的行为是可预期的：学生会变成教师的样子，没有引入新的病态。所以蒸馏路线的上限取决于教师。**只要先把专家训强，「用小专家去蒸馏大模型」就是值得押注的方向**，而权重合并即便专家变强了，也仍然要面对干扰问题。

还有一个方法论上的收获：分数在地板附近时，**评测噪声可能比模型之间的差距还大**。本地 8B judge 一度让 Linear 的 HLE 看起来提升了 +6.8 且显著，审核后只剩 +2.0 且不显著。没有逐题去看原始输出，就会得出完全错误的结论。

## 如果再来一次

1. **先把专家训强**：TB2 / SWE 用真实的多轮 agent 轨迹，HLE 用「Explanation / Answer / Confidence」格式的高难推理数据，ASI 用科学计算代码数据。目标是每个专家在本领域显著超过 base。
2. **按我原来的设想做蒸馏**：4 个专家（以及 base）各自在本领域生成轨迹，按结果过滤，混合成一份数据，去训练一个更大的学生（例如 Qwen3-14B），之后再做 on-policy 蒸馏。目的是让学生学到专家之间的「高级共性」，而不是对参数做平均。
3. **用生成式开发集选模型**：teacher-forced loss 选中了 TIES，却完全看不到它的格式接管。每个领域留几十条题目做真实生成 + 格式检查，才能选对模型。
4. **评测规范化**：官方 judge、TB2 跑 5 次、SWE 跑完整的 HARD-51。在地板附近，只有足够多的样本和干净的判分，才能看清 1–3 个点的差别。
